# 保护区鸟类普查名录对照系统

用最新版名录比较历年鸟类普查数据的网页应用：Flask + SQLite，Docker Compose 一键启动。

## 启动

```bash
# Docker（推荐）
docker compose up --build
# 打开 http://localhost:8000

# 本地开发
pip install -r requirements.txt
python3 run.py            # 默认 http://127.0.0.1:8000，PORT 环境变量可改端口
```

SQLite 数据库位置由 `BIRDAPP_DB` 指定（容器内默认 `/data/birdapp.db`，挂在命名卷
`birdapp-data`；本地默认 `./data/birdapp.db`）。首次启动自动建表。

## 数据格式（UTF-8 CSV）

**普查记录**：`记录号,年份,名录版,学名,只数`
- 记录号唯一；重传按记录号更新。原名/原版不变时只更新年份和只数并保留复核确认；
  原名/原版变更则清除该记录的旧确认。

**名录对照**：`起版,旧学名,下一版学名`
- 每行表示「起版 v → v+1 时，旧学名变为下一版学名」，版号为连续整数。
- 同一（起版, 旧学名）多行 = 拆种；多个旧学名指向同一名称 = 并种；未列出的名称沿用。
- 最新版号 = max（对照最大起版+1, 记录最大版号, 已确认最大版号, 正式名录最大版号）。

**正式名录（按版整份替换）**：`学名`（单列，一行一个学名）
- 在「正式名录」页选择版号后上传，**整份替换该版名单**；文件有误或保存失败时保留该版原名单。
- 换名单时**不扫描普查明细**；待核与否由下次汇总/待核页按生效数据重判。

`samples/` 下有可直接上传的示例：v1→v2 银鸥拆种、v2→v3 又并回（拆种后再并种），
赤嘴潜鸭 v1→v2 拆种，一好一坏两份整份替换对照，以及 `checklist_v1~v4.csv`
各版正式名录、`checklist_bad.csv`（错误表头，用于验证整份拒绝）。

## 功能与规则实现

- **按年汇总**（/aggregate）：勾选最新版的一组物种。每条记录从其起点
  （已确认则从确认学名/确认版，否则从原名/原版）逐级追到最新版，得到可达学名集合 R：
  - R 全部落在所选组内 → 计入该年「最少」和「最多」；
  - R 只有部分落在组内 → 只计入「最多」，并列入「造成差额的原记录」；
  - 不相交 → 不计。
  计数以记录为单位，**同一笔计数即使沿多条路径（拆种后再并种）到达组内也只计一次**。
- **复核确认**（/records）：为整条记录确认一个学名和版号，系统校验该学名必须
  从原名按当前对照可追到（原版 ≤ 确认版 ≤ 最新版），否则拒绝；确认后汇总从确认版换算。
  可随时清除确认。
- **整份更换对照**（首页上传）：只扫描**已确认**记录，用新对照校验其确认学名/版号
  能否从原名追到；未复核的明细不参与校验。只要有追不到的，页面列出记录号并**保留旧表**；
  全部可追才在一个事务内 DELETE+INSERT 整表替换。
- **各版正式名录整份替换**（/checklists）：选择版号上传单列 `学名` CSV，即整份替换
  该版名单（事务内 DELETE+INSERT；文件解析失败或保存失败一律保留原名单）。上传过程
  不扫描普查明细、不校验记录，名单是否影响待核留给下次计算按生效数据重判。
- **逐版核对与待核记录**（/review）：从每条记录当前的换算起点（已确认则从确认学名/
  确认版，否则从原名/原版）逐版核对到最新版：
  - 某版**没有正式名单**：该版不做收录核对，沿用原换算规则（对照未列出的名称原样带到下一版）；
  - 某版有正式名单：该版每个可达学名都必须被收录，任一未收录即记录「版号+缺名」；
  - **任一路径经过未收录学名，即使后来并回有效学名，也列入待核**，给出记录号、版号和缺名；
    待核记录整条暂不计入汇总，原明细（含复核确认）原样保留。
- **重判时机**：名单、对照、明细或复核确认有任何改动，下次汇总/待核页都按当前生效数据
  重新判定，不缓存旧结果。
- **单次汇总不混用新旧数据**：每次汇总在一个只读事务内一次性取对照表、正式名录与全部
  记录的同一已提交快照后再计算；汇总数字与待核清单来自同一状态（JSON 结果同时返回
  `years` 与 `pending_records`）。
- **并发**：SQLite WAL + busy_timeout；核查期间其他窗口仍可完成明细上传与复核
  （自测含 30 次并发汇总对 10 次上传+复核的读写并行用例）。
- CSV 任何一行校验失败则整份拒绝，不落半截数据。
- `POST /aggregate` 加 `format=json` 返回 JSON（含 `pending_records`、`checklist_versions`）；
  `GET /api/status` 返回库内统计（含 `pending_records`、`checklist_versions`）。

## 页面

- `/` 数据上传与库内统计（含待核条数、已覆盖正式名单的版号数）
- `/checklists` 各版正式名录管理（选版号、整份替换、查看各版收录数与预览）
- `/review` 待核记录（记录号、年份、换算起点、逐版缺名、最新版可达学名）
- `/records` 记录复核（含「待核缺名」列，待核行高亮）
- `/aggregate` 按年汇总（结果页同屏展示同一快照下的待核清单）
- `/mapping` 名录对照查看

## 已知限制（未完成项）

- 无登录与权限控制，复核操作不记录操作者和时间（无审计日志）。
- 记录复核页一次列出全部记录，未分页；数据量很大（数十万条）时页面和汇总会变慢，
  未做索引优化和异步计算；逐版核对在应用进程内完成，未做持久化缓存。
- 正式名录只能按版整份替换，不提供单条增删界面；未上传正式名单的版不做收录核对。
- 仅支持 UTF-8 CSV；Excel 直接另存的 GBK 文件需先转码。
- 名录对照只支持整份替换，不提供单条增删界面。
- 生产部署使用 Flask 内置服务器，高并发场景应换 gunicorn/waitress（镜像未内置）。
- 本沙箱环境无 Docker 守护进程，Compose 配置仅做静态核对；已用与容器相同的
  `run.py` 入口 + `BIRDAPP_DB` 走真实 HTTP 完成端到端自测。
